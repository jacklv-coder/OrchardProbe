# LAB-003 外部工件布局契约

[English](../research/lab-003-external-artifact-layout.md)

跟踪 Issue：[#84](https://github.com/jacklv-coder/OrchardProbe/issues/84)

状态：**检查点 1 已合并；检查点 2 无设备实现进行中**

LAB-002 因操作员提供的 Enrollment Receipt 与诊断日志被放在六个规范控制工件旁边，
最终以保留证据的流程性 No-Go 结束。LAB-003 是独立评审的后续步骤：先让每种文件系统
角色都明确且可测试；它不会重试或改写已关闭的 LAB-002 仪式。

## 范围与非目标

本检查点可以在不连接设备的情况下设计、实现和测试路径角色校验。它不得读取或修改
LAB-002 保留证据，不得操作手机、创建或消费授权信封、签名或上传 Build、安装或启动
App，也不得重新打开已关闭的生命周期 Lane。它不能证明已安装 Lineage、受保护到明文
转换、Go 结果、设备 Backend 或可用的 IPA 砸壳能力。

## 闭合目录角色

一个全新创建、仅 Owner 可访问的私有根目录包含三个互不重叠的子目录：

```text
private-root/                 mode 0700
├── experiments/             Host 创建的实验子目录
│   └── <opaque-id>/          六个基础控制工件，随后是允许的 Phase 目录
├── external-inputs/         只放操作员提供的 Receipt/Export
└── diagnostics/             只放操作员可见日志
```

这些名称表示角色，不是可复用的私有路径。实现必须使用已持有的目录描述符，且不得打印
解析后的私有根目录。

三个角色根必须是同一个已校验私有根的不同直接子目录，彼此不能嵌套或互为别名。选择实验
前 `experiments/` 必须为空，选择后只能包含唯一一个已选择的 Opaque-ID 子目录。每个路径
组件都必须是真实目录，Owner 与权限必须符合预期，并拒绝符号链接。每个实验子目录
在 Enrollment 关闭前只接受 Schema 定义的六个基础控制文件。有效状态转换后，只能由
现有原子 Phase Publisher 追加 Allow-list 中的 Enrollment/Run Control 或 Result 目录，
且每个 Phase 都有自己的精确固定清单。任何生命周期状态下都不得出现 Receipt、Export、
日志、临时文件、未知 Phase 或其他额外条目。

`external-inputs/` 最多只能包含一个直接子项，且该子项必须是有界、仅 Owner 可访问、
非符号链接的普通文件。诊断目标必须直接位于 `diagnostics/`，以不可替换方式创建，
并永远不能作为协议输入。实现必须在全部已打开角色对象之间拒绝相同文件系统身份（Device 与
Inode）；Host 文件系统可识别时也必须拒绝硬链接别名。

诊断属于闭合的保留输出：最多 16 个直接普通文件，单文件不超过 1 MiB，总计不超过
4 MiB。拒绝子目录、链接、特殊文件、替换及最终校验后的继续写入。已评审 Wrapper 必须
创建 Sink，把子进程输出限制在同一单文件上限和最多 30 秒墙钟时间内，并在最终校验前终止
完整子进程组；调用方任意重定向不属于可信诊断路径。

## 预检顺序

实现检查点必须在未来授权被创建或消费之前校验完整布局：

1. 打开并校验私有根及三个固定角色根；
2. 打开所选实验子目录，并校验当前生命周期 Phase 的精确清单：六个不可变基础控制
   工件，加上该状态已经允许的 Phase 目录及其固定内容；
3. 通过对应角色根描述符打开外部输入或预留诊断输出；
4. 校验包含关系、文件类型、Owner、权限、边界、无别名，并进行第二次稳定身份复核；
5. 只输出脱敏的角色级就绪信息，随后才允许现有协议 Parser 或 Signer 看到该描述符。

未来的关闭操作必须重复这些检查。还必须提供独立的无设备 Prepare/Preflight 入口，在
信封存在之前明确显示应使用的导入与日志角色。若把 Shell 日志重定向到实验子目录，会
形成不属于任何有效 Phase 清单的条目，并在创建授权前被预检拒绝。

## 失败、保留与脱敏

失败必须 Fail-Closed 且指出角色，例如“外部输入不在 external-inputs 角色内”或“实验
Phase 清单存在额外条目”。正常输出不得包含绝对路径、实验标识符、稳定设备标识符、
Fingerprint、Receipt/Export 内容、Host 结果或原始私有错误。

工具永远不移动、删除、重写或修复操作员提供的输入。它只能清理自己在正确角色根中
创建、尚未发布的临时文件。发布后的失败应保留本检查点新产生的 Owner-only 证据，等待
明确对账。LAB-002 保留文件始终在本检查点范围外，绝不能用来把旧 No-Go 制造成通过。

## 检查点 2 验收测试

合成测试必须覆盖有效三根布局，以及错误角色嵌套、祖先/后代重叠、符号链接组件、普通
文件替换、不安全 Owner/权限、严格子目录额外或缺失条目、两次检查间身份变化，以及支持
时的硬链接身份别名。测试还必须断言输入大小有界、Phase 状态转换有效/无效情况、诊断
文件排他创建、诊断单文件/条目数/总量/进程输出上限及 Maximum-plus-one 失败、清理
所有权，以及 stdout、stderr 和保留的脱敏错误中不存在私有值。
